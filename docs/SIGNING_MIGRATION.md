# Миграция подписи приложения

## Что изменено

Старая версия публиковалась как `com.artemiy.uprucheet`. Её keystore оказался в публичном репозитории вместе с паролями сборки. Считайте старую подпись раскрытой и не выпускайте с ней обновления.

Новая версия использует ID `com.artemiy.uprucheet.v2` и отдельный ключ. Она устанавливается рядом со старой, поэтому удалять прежнее приложение для перехода не требуется. Перенос данных выполняется через JSON-файл резервной копии.

Удаление keystore из текущей ветки не очищает предыдущие коммиты. Очистка публичной Git-истории потребует отдельного переписывания истории и согласования последствий для клонов и форков.

## Создание нового ключа

Создайте ключ на своём компьютере с установленным JDK. Команда запросит пароли и сведения о владельце сертификата:

```sh
keytool -genkeypair -v -keystore upr-uchet-v2.jks -alias upr-v2 -keyalg RSA -keysize 4096 -validity 10000
```

Храните keystore и пароли в надёжном месте. Не добавляйте файл keystore в Git и не отправляйте его в чат или мессенджер.

## Добавление GitHub Actions Secrets

В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте четыре секрета:

| Имя секрета | Значение |
|---|---|
| `UPR_SIGNING_KEYSTORE_BASE64` | Base64-содержимое файла `upr-uchet-v2.jks` |
| `UPR_SIGNING_STORE_PASSWORD` | Пароль хранилища, заданный при создании keystore |
| `UPR_SIGNING_KEY_ALIAS` | `upr-v2` |
| `UPR_SIGNING_KEY_PASSWORD` | Пароль ключа |

Получить Base64 для поля `UPR_SIGNING_KEYSTORE_BASE64`:

- Linux: `base64 -w 0 upr-uchet-v2.jks`
- macOS: `base64 upr-uchet-v2.jks | tr -d '\n'`
- Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upr-uchet-v2.jks"))`

Вставьте результат только в поле GitHub Secret. Workflow прекращает сборку, если любой из четырёх секретов отсутствует. Новый ключ не хранится в репозитории.

## Перенос данных на телефоне

1. В старой версии откройте настройки и сохраните резервную копию JSON в файл.
2. Установите APK версии 2. Старое приложение оставьте установленным.
3. В новой версии выберите восстановление из файла и импортируйте JSON-копию.
4. Проверьте задачи, CRM, заметки, связи и настройки. Отдельно проверьте разрешения календаря и напоминаний.
5. После проверки решите, когда удалить старую версию. Не пересылайте резервную копию через публичный репозиторий.

Новая версия имеет отдельное хранилище Android и не обновляет старую установку. Её обновления устанавливаются поверх версии 2 при сохранении нового ключа.
